Architecture & Design Rationale (In 60 Seconds)

⚖️

1. Saga Pattern vs. 2PC

Two-Phase Commit (2PC) blocks distributed databases while holding locks across network boundaries. The Saga pattern uses local ACID transactions followed by automated Compensating Actions if downstream services decline.

🔒

2. Relational Idempotency

Rather than relying on volatile Redis TTL keys that expire and risk double-charges on delayed retries, all services enforce PostgreSQL UNIQUE(transaction_id) constraints caught via IntegrityError.

🛡️

3. Row-Level Concurrency (CAS)

The Coordinator protects all status mutations under SELECT FOR UPDATE with Compare-And-Set (CAS) filters. Racing workers or client retries are serialized cleanly without sequence collisions.

📜

4. Append-Only SagaEvent Log

A single mutable status column destroys history. Every transition appends an immutable SagaEvent(seq, from, to, actor, payload) record, providing ground-truth forensic audibility.

⏱️

5. Deterministic Crash Recovery

A Celery Beat background worker sweeps orphaned non-terminal transactions older than 5 minutes, querying ground-truth downstream endpoints (/payments/check/, /reserve/check/) to roll forward or compensate.

📦

6. Microservice Isolation

Three independent Django services, three separate PostgreSQL databases. Zero shared database state. Completely isolated domain boundaries.
